# Playwright 浏览器工作流

当页面依赖 JavaScript 渲染、需要点击或填写表单、需要登录态，或必须观察真实页面状态时，使用 `browser_*` 工具。纯静态页面、公开 API、简单文本下载优先使用 curl 或搜索工具，它们更快且更省资源。

## 推荐流程

1. 用 `browser_navigate` 打开完整的 `http://` 或 `https://` 地址，先检查返回的标题、最终 URL 和正文摘要。
2. 交互前确认 CSS selector 稳定。优先使用唯一的 `id`、`name`、`data-*` 或语义属性，避免依赖易变的层级和 `nth-child`。
3. 用 `browser_click` 点击按钮或链接；用 `browser_type` 填写输入框。工具会等待 selector，但页面仍可能有动画、遮罩层或异步刷新。
4. 用 `browser_extract` 提取当前页面或指定区域的正文与链接。需要视觉证据或排查布局时，再用 `browser_screenshot`。
5. 完成后无需手动关闭浏览器；空闲到配置时间后会自动关闭。

## 点击与输入注意事项

- 元素找不到时，先重新提取页面内容，确认页面是否已跳转、selector 是否变化。
- Cookie 横幅、弹窗、加载遮罩可能挡住目标元素；先关闭遮罩，再执行点击。
- iframe 内元素不能直接使用顶层页面 selector。当前工具不提供 frame 切换时，应说明限制，或改用页面可访问的入口。
- 点击触发页面导航后，让下一次提取或导航操作承担等待；不要连续盲点多个元素。
- `browser_type` 使用填充语义，会清空原值。需要逐键输入、快捷键或复杂编辑器时，应说明当前工具限制。

## 内容提取与截图

- 默认 `browser_extract` 提取 `body`；页面很长时应提供更精确的 selector，减少噪声。
- JavaScript 延迟渲染内容若为空，重新提取或先点击页面上的加载入口。网络空闲不是所有站点的可靠完成信号。
- 截图路径必须位于工作区并以 `.png` 结尾；只有需要视觉核验时才截图，避免产生不必要的大文件。

## 登录与持久状态

需要复用登录时，在浏览器配置中设置专用 `userDataDir`。Cookies、本地存储和会话会保存在该目录。不要把包含凭据的 profile 提交到版本库，也不要在多个同时运行的浏览器进程之间共享同一个目录。登录验证码、多因素认证和人机验证通常需要用户亲自完成。

## 常见失败

- 浏览器未安装：运行 `npx playwright install chromium`。
- `element not found`：selector 错误、元素在 iframe 中、页面尚未渲染，或页面已经跳转。
- `timeout`：站点持续请求导致无法完全空闲、网络慢、元素被遮挡，或目标内容需要额外交互。
- JS 页面只有空壳：使用浏览器工具而不是 curl，并在导航后再次提取。
- 登录状态丢失：检查 `userDataDir` 是否固定、可写，且未被其他 Chromium 实例占用。

浏览器是较重资源。能用读取、搜索或 HTTP 请求完成的任务，不要启动浏览器；启动后复用同一页面，避免反复导航和大量截图。
